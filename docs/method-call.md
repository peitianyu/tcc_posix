# Receiver-first 方法语法糖（`a->f()` 指针注入）设计方案

日期: 2026-08-24
状态: 已定（**仅 `a->f()` 指针注入；方法首参必须为 `A*`；`.` 仅字段访问不触发方法糖**）

## 0. 背景与动机

在扩展 C 里补齐"对象方法调用"语法糖：给定 `struct A a;` 与一个接收 A 之指针的函数，
希望直接 `a->func(args)` 调用。`->` 把 receiver 按指针注入为第一参数：

```c
struct A a;
a->push_back(&v, 7);   // 方法首参是 A* → push_back(&a, 7)，可改容器状态
```

此特性对 STL 生态是净利好：容器方法可从显式的 `Vector_push_back(int)(&v, x)`（决策6的退化写法）
回退到贴近 C++ 的 `v->push_back(x)`。

**为何只保留 `->`（弃用 `.` 值注入）**：
- `a.f()` 值注入传**副本**，写 setter `a.set(x)` 内部改副本、对 `a` 无副作用 → 静默陷阱；
- 大结构体每次值拷贝有开销；只能匹配"首参为 struct 值"的方法，形态受限；
- `a->f()` 一套语法同时覆盖"值接收器"（自动 `&a`）与"指针接收器"（直接传指针），统一为
  "按指针传对象"，实现最简单、语义最自洽。

## 1. 语法与语义

- `a->f(x, y)`：`a` 为某 struct/union 类型的值，或指向该类型的指针。receiver 作为第 0 个
  实参注入，**方法首参必须为 `A*`**（`A` 为 receiver 的具名 struct/union 类型）。
  - `a` 是 **struct 值** → 自动注入 `&a`（形同 C++ `this=&a`，零拷贝、可改字段）。
  - `a` 是 **`A*`** → 直接注入 `a`（不再二次取址）。
- 是后缀表达式：`next()` 解析后续实参 `(x,y)`，把注入的 receiver 合成一趟 `gfunc_call`。
- **struct 内不内嵌任何函数**：方法糖纯粹是"结构体 + 同名全局函数（收 `A*`）"的字面配对，
  不改变 struct 布局、不新增字段、不改变 sizeof。

触发条件：post-op 遇 `->`（TOK_ARROW），对 receiver 所指类型的 `f` 做 `find_field`——
- 命中字段 → 走原字段路径（**字段优先**，标准 C 兼容零影响）。
- 字段缺失 **且** 下一 token 是 `(` → 进入方法糖。
- `.` 永远只做字段访问，不触发方法糖。

## 2. 函数绑定（同名 `f` + 首参类型核对，无拼接）

不拼接前缀、不做名字变形。设 receiver 的具名类型为 A（具名 struct/union 用标签名；
typedef 别名用别名；匿名且无 typedef 则无法命名 → 报错）。**只查同名全局函数 `f`**：

1. **方法函数的定义规约：第一个形参必须是 receiver 的指针 `A*`** —— 这是判别"是否收 A"的唯一依据。
2. 在全局函数符号表中按**方法名 token**（即 `f`）直接查找（名字唯一，无参数重载）。
3. 命中后**核对首参形态**：必须为 `A*` 且指向 receiver 的 struct；否则报
   `'f' has no callable method for this struct type`。
4. 同名 `f` 缺席 → 同上报错。

要点：与 C 的事实一致——函数名全局唯一，所以"同一个函数"只可能有一个；剩下的只是
**"这个函数是不是收 `A*` 的"** 一个类型判定。不采用 `A_f`，避免凭空制造符号、污染命名空间、
且与"字面 `a->f()`≈`f(&a)`"直觉冲突。

> 泛型实例（`Vector(int)`）的绑定见 §5——同样不做 `Vector_push_back` 式拼接。

## 3. 首参注入（`->` 指针语义，自动取值/取址）

- receiver 是 `A*` → 直接作为实参注入。
- receiver 是 `struct A` 值 → `test_lvalue()` 校验左值，置 `addrtaken` 固址到栈，
  `gaddrof()` 后 `mk_pointer()` 求得 `&a` 注入（零拷贝、可改容器状态）。
- 取址顺序：**先 `gaddrof`（r 去 LVAL）再 `mk_pointer`（type 改 `A*`）**，避免类型与
  `VT_LVAL` 冲突。

## 4. 类型检查与歧义

- 字段与方法同名：**字段优先**（与标准 C 一致，`.` 一律走字段）。
- 首参形态固定为 `A*`，作者无需显式写 `&`；值接收器自动取址。
- 重载：扩展 C 的 operator 是静态分派；`f` 用**名字唯一**，不做参数重载（同现有函数）。
- `a->field` 且 `a` 是**值接收器**（非指针）时报错：`-> 字段访问需指针接收器, 请改用 '.'`。

## 5. 泛型实例支持（含 model 泛型实例）

`Vector(int) v; v->push_back(7);` 也应是合法方法糖。仍**不做名字拼接**，改为**按首参类型
匹配已实例化（或触发实例化）的 model 方法**：

- STL/泛型容器的"方法"是 `model (T) void Vector_push_back(Vector(T) *self, T x)`，实例化为
  真实内部符号 `Vector_push_back_int`（concrete type）。方法糖对 `Vector(int)` 的
  `push_back` 需在模型层定位：**方法名 token `push_back` → 去该 receiver 泛型模板的方法表**里
  找到对应方法 → 复用它已实例化的符号（或触发实例化）。
- **编译器改动**：`unary` 方法回退需识别 receiver 类型是"model 泛型实例"，取其**泛型模板名**，
  在模板方法表（`model_list` 里的方法条目）按方法名查。
- 该修复同时解决决策6的崩溃（方法回退对泛型实例不再猜名崩）。

**关键澄清**：泛型实例的"方法名→内部符号"映射属于 model 层（模板知道自己的方法叫
`push_back` 而实例符号是 `Vector_push_back_int`），不属于 C 全局函数层。所以对普通 struct 走
"同名全局 `f`"，对泛型实例走"模板方法表"——都不拼接。普通 struct 若想用 `a->m()` 语法，函数
**必须命名为 `m`** 且首参为对应 `A*`。
